# Daily Reset

Daily Reset — iOS-приложение для отслеживания потребления воды, формирования полезных привычек и контроля ежедневного прогресса.

## Основные возможности

### Вода
- Отслеживание количества выпитой воды за день.
- Настраиваемая дневная цель.
- Добавление, редактирование и удаление записей о воде.
- История потребления воды.
- Статистика и прогресс относительно дневной цели.

### Привычки
- Создание и редактирование привычек.
- Отметка выполнения привычки за текущий день.
- Отмена отметки выполнения.
- Просмотр истории выполнения.
- Статистика и серии последовательных выполнений.

### Настройки
- Настройка дневной цели воды.
- Настройка напоминаний.
- Выбор светлой или тёмной темы.
- Настройки оформления приложения.
- Информация о приложении.

### Онбординг
- Первоначальное знакомство с приложением.
- Настройка начальной цели воды.
- Выбор параметров напоминаний.
- Сохранение факта завершения онбординга.

## Технологии

- **Swift** — основной язык программирования.
- **SwiftUI** — построение пользовательского интерфейса.
- **MVVM** — разделение интерфейса и логики представления.
- **SwiftData** — локальное хранение структурированных данных.
- **UserNotifications** — локальные уведомления и напоминания.
- **Git** — контроль версий.

В первой версии приложение работает локально на устройстве. Серверная часть, регистрация пользователей и облачная синхронизация не входят в первоначальный объём работ.

## Архитектура

Daily Reset использует SwiftUI и архитектурный подход MVVM с отдельным слоем сервисов.

Основные компоненты:

| Компонент | Ответственность |
|---|---|
| View | Отображение интерфейса и передача действий пользователя |
| ViewModel | Состояние экрана, обработка действий и бизнес-логика |
| Models | Модели данных приложения |
| Services | Работа с хранилищем и системными возможностями iOS |
| DesignSystem | Общие цвета, отступы и визуальные стили |
| Shared | Переиспользуемые компоненты интерфейса |

### Поток данных

1. Пользователь взаимодействует с View.
2. View передаёт действие соответствующей ViewModel.
3. ViewModel выполняет необходимую логику.
4. Данные сохраняются или извлекаются с помощью SwiftData и сервисов.
5. SwiftUI обновляет интерфейс на основании актуального состояния.

SwiftData может использоваться через `ModelContext` и механизмы наблюдения SwiftUI. Не нужно создавать дополнительный слой репозиториев для каждой модели, если он не даёт практической пользы.

## Основные разделы

### 1. Вода

Главный экран отображает:
- Выпитый объём за текущий день.
- Дневную цель.
- Визуальный индикатор прогресса.
- Быстрые действия для добавления воды.
- Список последних записей.

История воды открывается внутри раздела «Вода». Пользователь может просматривать записи за предыдущие дни и переходить к деталям отдельной записи.

### 2. Привычки

Главный экран отображает список активных привычек и прогресс за день.

Пользователь может:
- Добавить новую привычку.
- Изменить название или параметры привычки.
- Отметить выполнение.
- Отменить выполнение.
- Просмотреть историю и статистику.

История хранится отдельно от текущего состояния привычки, поэтому переименование привычки не должно стирать прошлые выполнения.

### 3. Настройки

Раздел объединяет настройки приложения и переходы к дополнительным экранам.

Настройки должны сохраняться между запусками приложения. Системные напоминания настраиваются через `NotificationService` и требуют корректной обработки разрешений iOS.

## Модели данных

### WaterEntry

Представляет одну запись о потреблении воды.

Основные поля:
- `id` — уникальный идентификатор.
- `amountML` — объём воды в миллилитрах.
- `date` — дата и время записи.

Записи используются для вычисления дневного объёма, истории и статистики.

### Habit

Представляет привычку пользователя.

Основные поля:
- `id` — уникальный идентификатор.
- `title` — название привычки.
- `createdAt` — дата создания.
- `isActive` — признак активной привычки.

При необходимости модель может расширяться описанием, категорией, целевым значением и другими параметрами.

### HabitCompletion

Представляет факт выполнения конкретной привычки за определённый день.

Основные поля:
- `id` — уникальный идентификатор.
- `habit` — связь с моделью `Habit`.
- `completedAt` — дата и время выполнения.
- `dayKey` — календарная дата выполнения, используемая для проверки уникальности.

Для одной привычки допускается не более одной активной записи выполнения на календарный день.

### AppSettings

Представляет настройки пользователя.

Основные параметры:
- `dailyWaterGoalML` — дневная цель воды.
- `appearanceMode` — выбранная тема.
- Параметры напоминаний.
- Признак завершения онбординга.

Настройки приложения должны быть централизованы, а не дублироваться в отдельных экранах.

## Правила бизнес-логики

### Учёт воды

- Все объёмы хранятся в миллилитрах.
- Дневной объём вычисляется суммированием записей за соответствующий календарный день.
- Изменение или удаление записи должно обновлять статистику.
- Дневная цель хранится отдельно от фактически выпитого объёма.

### Выполнение привычек

- Одна привычка может иметь максимум одно выполнение за календарный день.
- Повторное нажатие не должно создавать дубликат.
- Пользователь может отменить отметку.
- При отмене удаляется соответствующая запись выполнения.
- История за прошлые дни сохраняется.
- Серии и статистика вычисляются на основе записей выполнения.

### Даты и время

- Записи сохраняют дату и время события.
- При группировке по дням учитывается календарь и часовой пояс пользователя.
- Для проверки уникальности выполнения используется календарный день, а не только разница в 24 часа.
- Изменение часового пояса не должно приводить к случайному созданию дубликатов.

### Настройки

- Изменения настроек сохраняются локально.
- Изменение темы должно применяться ко всему приложению.
- Напоминания должны учитывать разрешения пользователя и выбранное расписание.

## Хранение данных

SwiftData используется для хранения:
- Записей воды.
- Привычек.
- Истории выполнения привычек.
- Настроек, если для них выбрана модель SwiftData.

`ModelContainer` создаётся на уровне приложения и передаётся в окружение SwiftUI.

`ModelContext` используется для добавления, изменения и удаления моделей.

Сервисный слой вводится там, где он упрощает работу с данными или системными API. Не следует дублировать возможности SwiftData дополнительной абстракцией без необходимости.

Для первой версии используется локальное хранение без обязательного подключения к интернету.

## Навигация

Основная навигация строится на `TabView` с тремя вкладками:

1. Вода.
2. Привычки.
3. Настройки.

Внутри вкладок используется `NavigationStack` для переходов к истории, деталям и формам редактирования.

Модальные формы, например создание привычки, могут открываться с помощью `sheet`.

Каждый раздел отвечает за собственные переходы, а корневой экран управляет основной структурой навигации.

## Дизайн-система

Визуальный стиль приложения:
- Светлая тема по умолчанию.
- Поддержка тёмной темы.
- Спокойные голубые акценты.
- Чистый фон и округлые карточки.
- Единые отступы, размеры элементов и типографика.
- Поддержка системных настроек доступности iOS.

Цвета и размеры должны быть централизованы в `DesignSystem`, чтобы не дублировать значения в каждом экране.
